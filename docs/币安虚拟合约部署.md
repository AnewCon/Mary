# QuantOS 币安虚拟合约

React、Vite 和原雪景像素素材继续使用。Cloudflare Pages 提供前端，QuantOS Worker 提供 API 与每分钟结算，独立 MCP Worker 通过服务绑定调用 API。生产启用 `VIRTUAL_ONLY=true` 时，旧欧易同步、订单和保护写入口全部禁用，成交与账单保留在欧易只读归档。

## 计价与结算

- 只使用 `https://fapi.binance.com` 的固定公开 GET 行情接口。成交价、成交价 K 线、标记价和各自时间分别展示。标记价和资金费率仅供分析。当前资金费不记入虚拟余额。
- 记录 AI 决策价格和时间、理由、版本与分析快照。成交使用有效最新成交价，按买卖方向加不利滑点并按价格步长取整。默认手续费为 5 基点、滑点为 2 基点、最大开仓偏差为 50 基点，可在账户设置中修改。默认本金 80 USDT。
- 资金与数量使用 12 位十进制定点 BigInt。市场数量向下按交易所步长取整，释放保证金按数量比例分配，最后一笔释放全部剩余保证金。保护档位按累计比例分配，100% 的最后一档接收舍入余量，低于 100% 的部分继续由统一止损覆盖。
- 逐仓采用虚拟保证金耗尽模型，缺口损失封顶于该段保证金。它不等于币安真实维持保证金模型。已结算盈亏按账本逐笔汇总，最大回撤使用已提交的权益快照。MFE/MAE 使用处理后的价格区间估计。
- 仓位游标按毫秒保存。开仓后的首个不完整分钟以及手动修改前的不完整分钟读取聚合成交；完整分钟逐根读取成交价 OHLC。数据缺口不推进受影响的仓位游标。同一根覆盖止盈和止损先走不利路径并标记歧义。止损跳空使用开盘价与触发价中更差者，再计滑点；止盈保守地从目标价计滑点。
- D1 批事务同步提交账户、仓位游标、事件及请求结果。互斥租约带事务内所有权校验，Cron 和手动结算竞争时返回忙，复用原请求 ID 可查询或重试。影子仓位有独立事件，排除在正式虚拟资金之外。
- 当前最多 4 个同时活跃合约、12 笔主仓位（含影子最多 36 笔），历史按每仓每轮最多 90 根回补。每轮外部行情请求带预算，超额留给后续 Cron；策略统计取最近 1,000 笔已结束主仓位。

## 测试与迁移

运行 `npm run build` 和 `npm test`。`tests/virtual.test.mjs` 用独立 Miniflare D1、固定的公开行情响应和真实 MCP 服务绑定走完开仓、逐分钟回补、分段退出、查询历史和请求状态。生产挑战账本不用于测试。

`migrations/0006_virtual.sql` 只创建 `virtual_*` 表及默认实验账户。在隔离库运行全部迁移后，可以验证本地页面。生产迁移前导出 D1 备份并保留当前 Worker 版本与 Pages 提交。确认测试环境币安行情、真实线上 Cron、MCP 鉴权与端到端入场后，按以下顺序部署：

1. 对生产 `quantos-db` 执行 `0006_virtual.sql`。保留原表和欧易历史记录。
2. 构建并部署 `wrangler.jsonc` 对应 Worker，再部署 `wrangler.mcp.jsonc` 对应 MCP Worker。确认 `VIRTUAL_ONLY=true`、两个旧模拟交易开关为 `false`。
3. 将审阅过的分支合入 Pages 使用的分支。确认现有 `API` 与 `MCP` 服务绑定以及 `/mcp` 路径可用。
4. 通过管理员界面给专用连接器 Key 增加 `virtual_trade` 范围，保留必要 `read`。更新原私有 Sites 连接器，手机新建聊天重新选择它。API 密钥轮换后更新 Sites Secret。
5. 使用单独实验账户检验开仓记录、逐档保护、市场缺口错误和历史查询。正式账本启用前检查生产 Cron 与市场状态。

回滚时恢复切换前的 Pages 提交与 Worker 部署版本，先保留新的 `virtual_*` 表供复盘。恢复旧版本会重新启用旧环境的接口与 Cron，需确认符合实际切换目的。数据库备份应保存于非公开位置。

## ChatGPT 工具

现有 Pages MCP 地址 `https://marya-4j3.pages.dev/mcp`。测试环境使用自己的 MCP Worker 地址。

- `get_virtual_market` 读取闭合日线、15 分钟线、最新成交价、标记价、成交量、持仓量和资金费率。
- `sync_virtual_trade` 接受 `OPEN`、`CLOSE`、`UPDATE_PROTECTION`。只有 `COMMITTED` 表示已写入账本。请求超时用原 UUID 查 `get_virtual_request_status`。
- `get_virtual_portfolio`、`get_virtual_position`、`get_virtual_history`、`get_virtual_statistics` 支持复盘，历史分页用 `nextCursor`。
- `quantos_get_history` 在虚拟模式下用于读取单独保存的旧欧易历史。

外部行情不可用时必须保留错误状态，不能填入测试行情或宣称开仓成功。资金费自动扣结、移动止损、长期权益曲线及真实网络的逐笔撮合仍可继续完善。
