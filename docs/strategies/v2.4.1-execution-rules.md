# QuantOS V2.4.1-DAILY-PUMP-FILTER 执行规则

形成时间为 2026 年 11 月 16 日。本文件整理自用户提供的历史讨论恢复版。适用于 Binance Testnet USDⓈ-M 永续合约 T+0 模拟交易，尚无独立回测结论。

## 已确认的历史执行规则

| 项目 | 口径 |
| --- | --- |
| 账户与规模 | 只使用 Binance 模拟盘。单轮 80 USDT，默认 10 倍杠杆，同时最多 5 个币种，不强制开满，优先等待合理区间的限价入场。 |
| 涨幅过滤 | 最近 14 根已收盘 UTC 日 K。任一天 (close/open−1) ≥300% 时排除普通追多；(high/low−1) ≥400% 触发极端波动过滤。极端暴涨后至少 7 根完整日 K 冷却。暴涨后急跌不能单独作为做空理由。 |
| 趋势与时机 | 4H 与 1H 同向；15M 核验回踩、反弹或结构确认，5M 辅助入场。周期冲突、结构未确认或仅有连续涨跌时输出 WAIT。 |
| 两项评分 | 方向分和入场分独立，均为 0–100，且都必须 ≥80。方向分不是盈利概率。有高分时仍执行后续全部校验。 |
| 风险预算 | 计划保证金合计 ≤32 USDT，计划止损合计 ≤2 USDT，合计包含已有持仓、拟新增订单及仍可能成交的挂单。止损风险用入场价到止损价的距离乘数量，并计入适用的手续费、滑点和资金费等预估成本。优先以扣除成本后的净收益／计划亏损 ≥1.8 为准。 |
| 相关性 | 同方向候选相关系数 ≥0.85 时优先保留更优的一笔；主流币同向敞口不能按独立风险计算。 |
| 限价管理 | 交易所确认创建后 45 分钟触发撤单，撤后回查实际状态。部分成交则检查并保护实际仓位，撤销余量。提交超时用同一请求 ID 查单。 |
| 保护验收 | 提交前核对合约状态、价格方向、数量精度、杠杆、资金及保护计划。成交后核对实际委托和仓位，止盈止损各自回读并覆盖实际仓位。保护异常时暂停新开仓、撤未成交余量并报告实际仓位。 |

核验顺序为候选及流动性 → 14 日过滤 → 4H、1H、15M、5M → 两项评分 → 相关性与组合预算 → 保护计划 → 授权模拟限价 → 回读及撤单 → 复盘。成交到保护确认有风险窗口。自动紧急平仓不属于这份恢复版。

## 历史不一致与未固定口径

- 历史示例的单笔风险并非始终 ≤0.35 USDT。研究校验器默认使用 0.35 USDT 作为保守上限，可在测试调用显式传入不同值；不得据此改写历史记录。
- 历史只明确 5M 的角色与顺序，未定义突破根数、成交量倍率及回踩容差。研究校验器要求人工独立确认，未把 V2.5 实验算法当作旧公式。
- 相关性的收益周期、计算窗口未定。研究校验要求已有同向风险敞口的相关性有外部核验；缺失时待核查。正式对比测试应预先登记窗口，并在旧策略和辅助策略两轮使用同一窗口。
- 历史评分的统一数学公式尚未恢复。旧规则分数须单独提交给研究校验器；V2.5 分数即使数值超过 80 也不能代替。没有独立回测和明确升级批准前，V2.5 分析保持只读。
- 当前日线校验将两个异常阈值都视作冷却触发。这是保守实现约定。满 7 根后，14 日窗口内曾出现 ≥300% 收盘涨幅的币种仍排除普通追多。

## 五币研究筛选

确认 BTC、ETH、SOL、ZEC、NEAR 的自然 OI 样本均覆盖至少连续 24 小时，并验证每币的 24h OI 基准可用。测试选同一数据截点，两轮均使用同一批已收盘 K 线、同一账户敞口、费用、风险预算和相关性窗口。第一轮只看旧执行证据，第二轮补充 V2.5 的 OI、资金费率和清算数据。逐币记录两项独立评分、每道门槛、WAIT 原因与两轮差异。以影子筛选方式执行，保留观察结果供后续回看。
